# EPH Live ISO

The EPH runtime is a reusable Debian 12 Live ISO that boots entirely into RAM (toram), starts a single-node K3s Kubernetes cluster, and runs the EPH Agent as a Kubernetes Deployment Pod. It does not install an operating system to local disk.

## Build

Build on Debian 12/bookworm with live-build, xorriso, squashfs-tools, wget, ca-certificates, and debootstrap.

~~~bash
sudo env \
  K3S_VERSION=v1.35.3+k3s1 \
  K3S_SHA256_AMD64=<verified-64-character-sha256> \
  bash eph-iso/build.sh
~~~

The builder supports amd64 and Kubernetes minors v1.33, v1.34, v1.35, and v1.36. Pin the K3s release and verify its official SHA-256 independently. The output directory receives the ISO, SHA-256 sidecar, and release metadata JSON.

## Per-node configuration with cloud-init NoCloud

Use one generic ISO for every machine. Do not rebuild the ISO to inject per-node identity, network settings, or credentials. Generate a separate NoCloud seed image for each EPH node and attach it as a second virtual disk/CD-ROM or expose it through approved virtual media.

The seed volume must use the filesystem label CIDATA and contain these files at its root:

- user-data: cloud-config that writes the node bootstrap configuration and control-plane CA trust.
- meta-data: unique instance ID and hostname.
- network-config: cloud-init v2 network configuration for the site's interfaces.

Example source files are in eph-iso/examples/cloud-init/. Replace all placeholders with values generated by the Cloud Control Plane. Example seed layout:

~~~text
CIDATA/
  user-data
  meta-data
  network-config
~~~

A seed ISO can be produced with cloud-localds from the cloud-image-utils package:

~~~bash
cloud-localds --filesystem=iso \
  --network-config=eph-iso/examples/cloud-init/network-config \
  eph-node-seed.iso \
  eph-iso/examples/cloud-init/user-data \
  eph-iso/examples/cloud-init/meta-data
~~~

For production, the Cloud Control Plane must render a unique user-data document per node. It must inject:
- control_url, node UUID, one-time enrollment token, and immutable EPH Agent image reference pinned by SHA-256 digest.
- The trusted CA certificate used to verify the Cloud Control Plane HTTPS endpoint. The EPH node generates its own private key and CSR after boot; the Cloud Control Plane exchanges the one-time token for a Vault-signed node certificate and a new runtime token.
- Optional CAPI pivot kubeconfigs only when both source and target kubeconfigs are present and the workflow authorizes their use.

Cloud-init writes the bootstrap configuration and control-plane CA under /etc/ai-agent-studio/eph-bootstrap with root ownership and restrictive permissions. The EPH bootstrap systemd unit waits for cloud-init and network readiness, starts after K3s, generates a private key locally with OpenSSL, submits a CSR using the one-time token, verifies the returned certificate fingerprint and public-key match, then creates Kubernetes Secrets with the new node-bound runtime token and mTLS identity. It applies the dedicated EPH Agent RBAC and Deployment and waits for the Agent rollout.

The example user-data contains obvious placeholders and is not deployable as-is. Never commit real enrollment tokens, private keys, kubeconfigs, or customer network details. Do not put per-node secrets in the generic ISO, kernel command line, build logs, or shared seed images. The seed contains a short-lived one-time enrollment token; the API consumes it only after Vault PKI signs the CSR and returns a separate node-bound runtime token. The node private key is never sent to the API or placed on the seed media. Protect seed media as secret material and destroy it after provisioning.

## Network configuration

Use cloud-init's NoCloud network-config to configure DHCP or static addressing, bonds, VLANs, bridges, and interface matching. Do not assume a fixed interface name or MAC address. The example profile uses a wildcard match for illustration; production profiles must be rendered from the site's network inventory and validated against the actual NIC topology.

## Runtime layout

- Debian Live root filesystem: toram; no local-disk installation.
- cloud-init: NoCloud datasource from a per-node CIDATA seed.
- K3s server: systemd service; one-node Kubernetes control plane.
- /var/lib/rancher/k3s and /var/lib/kubelet: tmpfs; cluster state is disposable.
- EPH Agent: Kubernetes Deployment Pod in ai-agent-system; not Docker Compose and not a host process.
- Container image: immutable SHA-256 digest.
- CNI: K3s default Flannel, independent of the target cluster's Calico/Multus/OVS/SR-IOV design.

## Safety and limitations

This increment builds the Live ISO and injects per-node configuration through cloud-init NoCloud. It does not yet perform real CAPI pivot, Metal3/Ironic provisioning, BMC operations, or EPH host reclaim. These require separate guarded workflow phases and explicit approvals.

The temporary cluster and its kubelet state are intentionally lost at power-off. Persist workflow checkpoints, hardware identity, audit records, and all deployment state in the Cloud Control Plane before any reboot or reclaim. A successful ISO boot is not permission to mutate Ironic, BMC, CAPI, or target-cluster resources.
